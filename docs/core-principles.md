# 핵심원칙

## 바이브코딩이란

바이브코딩에서 **사람은 코드를 쓰지 않습니다.** AI가 코드를 씁니다.

그렇다면 사람의 역할은 무엇인가? **AI가 실수 없이 정확하게 코딩하도록 환경을 만들고, 무엇을 만들지 판단하는 것**입니다.

좋은 감독은 직접 연기하지 않지만, 배우가 최고의 연기를 하도록 연출합니다. 바이브코딩에서 사람은 코더가 아니라 감독입니다.

## 세 가지 핵심 역할

### 1. 환경 구축 — AI가 실수할 수 없는 구조를 만든다

코딩 실력이 아니라 **시스템 설계 능력**이 핵심입니다.

vue-zero처럼 빌드 에러가 원천 불가능한 프레임워크를 선택하고, CLAUDE.md로 맥락을 주고, rules로 금지 사항을 정하고, hooks로 강제하는 것. 이 환경이 잘 갖춰지면 AI는 거의 실수하지 않습니다.

환경이 부실하면 AI는 매번 다른 패턴으로 코드를 생성하고, 프로젝트 규칙을 어기고, 빌드가 깨집니다. 사람이 코드를 보고 고쳐야 합니다. **이건 바이브코딩이 아닙니다.**

### 2. 판단 — AI가 할 수 없는 결정을 한다

"무엇을 만들 것인가", "이 기능이 정말 필요한가", "삭제는 soft delete인가 물리 삭제인가", "권한은 누구에게 줄 것인가" — 이런 **도메인 판단과 비즈니스 결정**은 사람의 영역입니다.

AI는 코드를 생성할 수 있지만 비즈니스 맥락을 모릅니다. 고객이 원하는 것, 법적 제약, 운영 현실을 아는 건 사람입니다.

### 3. 커뮤니케이션 — AI에게 효과적으로 의도를 전달한다

같은 기능을 요청해도 **맥락을 얼마나 잘 전달하느냐**에 따라 결과가 완전히 달라집니다.

```
❌ "게시판 만들어줘"
✅ "게시판 만들어줘. 삭제는 soft delete로, 본인과 관리자만 가능하게.
    첨부파일은 R2에 저장하고, 목록에서는 썸네일만 보여줘."
```

코드를 읽는 능력보다 **AI에게 의도를 정확히 전달하는 능력**이 더 중요합니다.

## 환경 구축의 도구들

AI 개발 환경을 구성하는 도구들입니다. 각 도구의 역할과 관계를 이해하면 효과적으로 환경을 설계할 수 있습니다.

### 도구별 역할

| 도구 | 역할 | 비유 |
|------|------|------|
| **CLAUDE.md** | 프로젝트 맥락을 알려줌 | 신입 개발자에게 주는 온보딩 문서 |
| **rules** | 반복 실수를 금지함 | 교통 법규 |
| **hooks** | 금지를 어기면 즉시 잡음 | 과속 카메라 |
| **templates** | 올바른 패턴을 알려줌 | 신입에게 주는 코드 샘플 |
| **skills** | 복잡한 절차를 자동화함 | 업무 매뉴얼 |
| **프레임워크 선택** | 실수 가능성을 원천 제거 | 안전한 도로 설계 |

### 방어의 3단계

```
1단계: CLAUDE.md — "이런 프로젝트야" (맥락 제공)
   ↓ 세션이 길어지면 밀릴 수 있음
2단계: rules — "이건 하지 마" (규칙 반복 주입)
   ↓ 규칙을 어겨도 감지 안 됨
3단계: hooks — "어기면 즉시 잡는다" (기계적 강제)
```

**가장 확실한 방어선은 hooks입니다.** CLAUDE.md는 세션이 길어지면 컨텍스트에서 밀릴 수 있고, rules는 어겨도 아무 일이 안 생기지만, hooks는 기계적으로 실행되어 **절대 잊지 않습니다.**

### 무엇을 어디에 넣을지

| 내용 | 적합한 위치 | 이유 |
|------|------------|------|
| 프로젝트 개요, 기술 스택 | CLAUDE.md | 맥락 정보 |
| "JSP에 HTML 금지" 같은 필수 규칙 | rules | 반복 주입 필요 |
| Options API만 사용 강제 | rules + hooks | 규칙 + 기계적 검증 |
| 맑은프레임워크 JSP/HTML 분리 패턴 | templates | AI가 추론하기 어려운 구조 |
| 배포 체크리스트 | skills | 순서가 중요한 멀티스텝 |

### 환경이 성숙하면 일어나는 일

환경이 잘 갖춰지면:

- AI에게 "사용자 관리 기능 만들어줘"라고 한 마디만 하면 됩니다
- AI가 프로젝트 규칙에 맞는 코드를 생성합니다
- hooks가 규칙 위반을 즉시 잡아서 AI가 스스로 수정합니다
- 사람은 코드를 보지 않고 결과(화면)만 확인합니다

**이것이 바이브코딩의 이상적인 상태입니다.**

## 보안 정책

AI가 자율적으로 코딩할 때 반드시 지켜야 할 보안 가드레일입니다. CLAUDE.md 또는 rules에 명시하세요.

- **API 키, 시크릿을 코드에 하드코딩 금지** — 환경 변수로만 관리
- **.env 파일 읽기/출력 금지** — AI가 시크릿에 접근하지 못하게
- **운영 DB 직접 연결 금지** — 로컬/개발 환경만 사용
- **외부 API 호출은 사전 승인 필요** — 허용된 서비스만 호출

## 비용 통제

- **세션이 길어지면 새로 시작** — 컨텍스트가 누적될수록 토큰 비용 증가. CLAUDE.md와 rules가 자동으로 컨텍스트를 복원해주므로 새 세션 시작 비용이 낮음
- **hooks로 토큰 절약** — AI가 스스로 검증하는 과정(파일 읽기 → 린트 → 결과 확인)을 Hook 한 줄이 대체
- **대형 문서 분할** — 500줄 이상의 문서는 분할하여 필요한 부분만 로딩

## 체크리스트

바이브코딩 환경 구축 확인:

**환경 구축:**
- [ ] 빌드 에러가 적은 프레임워크를 선택했는가?
- [ ] CLAUDE.md에 프로젝트 맥락이 있는가?
- [ ] rules에 AI가 반복 실수하는 패턴이 금지되어 있는가?
- [ ] hooks가 규칙 위반을 자동으로 잡아내는가?
- [ ] 보안 규칙이 명시되어 있는가?

**판단:**
- [ ] 비즈니스 로직 결정을 AI에게 맡기지 않고 사람이 하고 있는가?
- [ ] 도메인 지식이 필요한 부분을 명확히 AI에게 전달하고 있는가?

**커뮤니케이션:**
- [ ] AI에게 "뭘 만들지"뿐 아니라 "왜, 어떤 맥락에서"도 전달하고 있는가?
- [ ] 프롬프트에 구체적인 조건과 제약을 포함하고 있는가?
