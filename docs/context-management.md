# 컨텍스트 관리 및 체크포인트

## 개요

Claude Code는 대화가 길어지면 초기 컨텍스트를 잃을 수 있습니다. 장시간 작업 시 중간 요약, 체크포인트, 작업 이력 관리를 통해 **Claude Code의 집중력을 유지**할 수 있습니다.

## 왜 필요한가?

AI는 대화가 길어질수록:
- 초기 지시사항을 잊어버림
- 프로젝트 구조를 혼동
- 이전 작업 내용을 놓침
- 일관성이 떨어지는 코드 생성

**해결 방법:**
- 중간 요약 및 체크포인트
- 작업 이력 기록 (`.claude/memory`)
- 새 세션 시작 타이밍

## 컨텍스트 관리 전략

### 1. 중간 요약 (50% 규칙)

작업이 50% 진행되면 현재까지의 성과를 요약합니다.

**프롬프트 예시:**
```
"지금까지 작업한 내용을 정리해줘:
- 완료한 기능
- 수정한 파일 목록
- 남은 작업
- 주의사항"
```

**Claude Code 응답 예시:**
```markdown
## 완료한 기능
1. 사용자 CRUD API 완성
   - GET /users (목록)
   - POST /users (생성)
   - PUT /users/:id (수정)

## 수정한 파일
- src/routes/users.js (생성)
- src/services/userService.js (생성)
- src/index.js (라우트 등록)

## 남은 작업
- DELETE /users/:id 추가
- 권한 체크 추가
- 테스트 작성

## 주의사항
- 서비스 레이어는 반드시 클래스 기반
- KV 캐시 사용 필수
```

### 2. 체크포인트 생성

큰 작업이 완료되면 체크포인트를 만듭니다.

**프롬프트 예시:**
```
"지금까지 작업한 내용을 CHECKPOINT.md 파일로 저장해줘.
다음 세션에서 이어서 작업할 수 있도록."
```

**생성되는 파일 예시 (CHECKPOINT.md):**
```markdown
# 체크포인트 - 2024-01-24 15:30

## 완료한 작업
- 사용자 CRUD API 완성
- KV 캐시 적용
- 에러 처리 추가

## 다음 작업
1. 권한 체크 미들웨어 추가
2. 테스트 작성
3. API 문서 업데이트

## 주의사항
- PUBLIC_PATHS에 인증 불필요 경로 추가 필요
- D1 스키마에 role 컬럼 추가 예정
```

### 3. 새 세션 시작 타이밍

다음 상황에서는 새 세션을 시작하세요:
- 작업이 50% 이상 진행됨
- 대화가 30-40회 이상 진행됨
- Claude Code가 이전 지시를 잊는 것 같을 때
- 새로운 큰 기능을 시작할 때

**새 세션 시작 방법:**
1. 현재 작업 요약 받기
2. CHECKPOINT.md 생성
3. 새 세션 시작
4. "CHECKPOINT.md를 읽고 이어서 작업해줘"

## `.claude/memory` 활용법

`.claude/memory` 폴더는 **공식 기능은 아니지만** 장기 프로젝트에서 작업 이력을 기록하는 실용적인 방법입니다.

### 언제 필요한가?

다음 상황에서 유용합니다:
- 여러 날에 걸쳐 진행되는 프로젝트
- 여러 개발자가 돌아가며 작업
- 복잡한 리팩토링 진행 중
- 점진적 기능 추가

### 구조

```
.claude/
├── rules/              # 개발 규칙 (변하지 않음)
├── templates/          # 코드 템플릿 (변하지 않음)
└── memory/             # 작업 이력 (계속 변함)
    ├── status.md       # 현재 상태
    ├── history.md      # 작업 이력
    └── next-tasks.md   # 다음 할 일
```

### status.md - 현재 상태

프로젝트의 현재 진행 상황을 기록합니다.

```markdown
# 프로젝트 현재 상태

**마지막 업데이트:** 2024-01-24 15:30

## 진행 중인 작업
- 사용자 권한 관리 시스템 개발 중
- 현재 단계: API 엔드포인트 완성, 권한 체크 미들웨어 작업 중

## 완료된 주요 기능
- [x] 사용자 CRUD API
- [x] JWT 인증
- [x] KV 캐시 적용
- [ ] 권한 관리 (진행 중)
- [ ] 관리자 대시보드 (예정)

## 최근 변경사항
- src/services/userService.js: KV 캐시 추가
- src/middleware/auth.js: JWT 검증 로직 개선
- src/routes/users.js: 에러 처리 강화

## 알려진 문제
- D1 데이터베이스 스키마에 role 컬럼 추가 필요
- KV TTL 설정 최적화 필요

## 다음 단계
1. 권한 체크 미들웨어 완성
2. 관리자 전용 엔드포인트 추가
3. 테스트 작성
```

**크기 제한:** 1,000-1,500 토큰 (약 3,000-4,500자)

### history.md - 작업 이력

주요 작업 이력을 날짜순으로 기록합니다.

```markdown
# 작업 이력

## 2024-01-24
### 완료
- 사용자 CRUD API 완성
- KV 캐시 적용 (1시간 TTL)
- 에러 처리 미들웨어 추가

### 변경 파일
- src/routes/users.js (생성)
- src/services/userService.js (생성)
- src/middleware/errorHandler.js (수정)

### 주의사항
- 서비스 레이어는 클래스 기반으로 유지
- env 주입은 생성자에서

## 2024-01-23
### 완료
- 프로젝트 초기 설정
- D1 데이터베이스 스키마 설계
- JWT 인증 미들웨어 추가

### 결정사항
- Hono 프레임워크 사용
- D1 + KV 조합으로 성능 최적화
```

**크기 제한:** 최근 5-10개 이력만 유지 (2,000 토큰 이내)

### next-tasks.md - 다음 할 일

우선순위별 작업 목록을 기록합니다.

```markdown
# 다음 할 일

## 우선순위 높음
- [ ] 권한 체크 미들웨어 완성
  - `isAdmin()`, `hasPermission()` 함수 추가
  - src/middleware/permission.js 생성

- [ ] 관리자 전용 엔드포인트 추가
  - GET /admin/users (전체 사용자 목록)
  - PUT /admin/users/:id/role (역할 변경)

## 우선순위 중간
- [ ] 테스트 작성
  - 서비스 레이어 유닛 테스트
  - API 엔드포인트 통합 테스트

- [ ] API 문서 업데이트
  - OpenAPI 스키마 작성
  - Swagger UI 추가

## 우선순위 낮음
- [ ] 로깅 개선
- [ ] 성능 모니터링 추가

## 보류
- 웹소켓 실시간 알림 (v2.0에서 진행)
```

**크기 제한:** 1,000 토큰 이내 (약 3,000자)

## 실전 활용 예시

### 시나리오: 3일간 진행되는 프로젝트

**Day 1 - 오전 (작업 시작)**
```
프롬프트: "사용자 관리 기능을 만들어줘. CRUD API와 JWT 인증을 포함해서."
```

**Day 1 - 오후 (체크포인트)**
```
프롬프트: "지금까지 작업 내용을 .claude/memory/status.md에 저장해줘."
```

**생성된 status.md:**
```markdown
# 현재 상태

**마지막 업데이트:** 2024-01-24 14:00

## 완료
- 사용자 CRUD API
- JWT 인증 미들웨어

## 다음 작업
- 권한 관리 시스템
- 테스트 작성
```

**Day 2 - 오전 (작업 재개)**
```
프롬프트: ".claude/memory/status.md를 읽고, 권한 관리 시스템을 만들어줘."
```

**Day 2 - 오후 (체크포인트 업데이트)**
```
프롬프트: "status.md를 업데이트하고, history.md에 오늘 작업 내용을 추가해줘."
```

**Day 3 - 마무리**
```
프롬프트: ".claude/memory/를 참고해서 남은 작업을 완료해줘."
```

## `.claude/memory` 장단점

### 장점
- ✅ 장기 프로젝트의 연속성 유지
- ✅ 여러 개발자 간 컨텍스트 공유
- ✅ 작업 중단 후 재개가 쉬움
- ✅ 프로젝트 진행 상황 파악 용이

### 단점
- ❌ 토큰 수 증가 (성능 저하 가능)
- ❌ 수동 관리 필요
- ❌ 공식 기능 아님 (향후 변경 가능)
- ❌ 너무 길어지면 역효과

### 사용 권장 사항
- 장기 프로젝트 (1주일 이상)에만 사용
- 파일당 1,000-2,000 토큰 이내 유지
- 오래된 이력은 삭제 (최근 것만 유지)
- 핵심 정보만 기록

## CLAUDE.md vs `.claude/memory`

### `CLAUDE.md` - 변하지 않는 정보
- 프로젝트 개요
- 기술 스택
- 핵심 아키텍처
- 영구적인 규칙

### `.claude/memory` - 계속 변하는 정보
- 현재 작업 상태
- 최근 변경 이력
- 다음 할 일
- 임시 주의사항

## 컨텍스트 최적화 체크리스트

작업 시작 전:
- [ ] CLAUDE.md가 최신 상태인가?
- [ ] `.claude/rules`가 프로젝트 패턴을 반영하는가?
- [ ] 이전 세션의 체크포인트가 있는가?

작업 중 (50% 진행):
- [ ] 중간 요약을 받았는가?
- [ ] 완료한 작업을 정리했는가?
- [ ] Claude Code가 규칙을 잘 따르는가?

작업 종료 시:
- [ ] 체크포인트를 생성했는가?
- [ ] `.claude/memory/status.md`를 업데이트했는가?
- [ ] 다음 할 일을 정리했는가?

## 토큰 수 관리

### `.claude` 폴더 전체 권장 크기
- **규칙 (rules)**: 10,000-15,000 토큰
- **프로젝트 개요 (CLAUDE.md)**: 3,000-5,000 토큰
- **템플릿 (templates)**: 필요한 만큼
- **작업 이력 (memory)**: 3,000-5,000 토큰
- **전체 합계**: 20,000-30,000 토큰 이내

### 초과 시 조치
1. `.claude/rules` 압축 (장황한 설명 제거)
2. CLAUDE.md 간소화 (핵심만 남김)
3. `.claude/memory` 정리 (오래된 이력 삭제)
4. 템플릿 개수 줄이기
