# 자주 사용하는 프롬프트 패턴

## 개요

Claude Code를 효과적으로 사용하기 위한 **검증된 프롬프트 패턴**을 제시합니다.

## 기본 패턴

### 1. 명확한 지시

**패턴:**
```
"[동작] + [대상] + [조건]"
```

**예제:**
```
✅ "User CRUD API를 만들어줘. Hono 프레임워크를 사용하고, D1 데이터베이스를 연결해줘."

❌ "사용자 API 만들어줘"
```

### 2. 컨텍스트 제공

**패턴:**
```
"[컨텍스트] + [요청]"
```

**예제:**
```
✅ "현재 프로젝트는 Cloudflare Workers를 사용해.
UserService 클래스를 참고해서 ProductService를 만들어줘."

❌ "ProductService 만들어줘"
```

### 3. 예제 기반 요청

**패턴:**
```
"[기존 예제] 참고해서 [새로운 것] 만들어줘"
```

**예제:**
```
✅ "src/routes/users.js를 참고해서 src/routes/products.js를 만들어줘.
동일한 CRUD 패턴을 사용해줘."
```

## 코드 생성 패턴

### 1. CRUD API 생성

**패턴:**
```
"[엔티티] CRUD API를 만들어줘.

요구사항:
- [GET] [엔드포인트] - [설명]
- [POST] [엔드포인트] - [설명]
- [PUT] [엔드포인트] - [설명]
- [DELETE] [엔드포인트] - [설명]

기술:
- [프레임워크]
- [데이터베이스]
- [추가 요구사항]"
```

**예제:**
```
"Product CRUD API를 만들어줘.

요구사항:
- GET /products - 목록 조회 (페이징, 검색)
- GET /products/:id - 상세 조회
- POST /products - 생성
- PUT /products/:id - 수정
- DELETE /products/:id - 삭제

기술:
- Hono 프레임워크
- D1 데이터베이스
- KV 캐시 사용
- 서비스 레이어 패턴"
```

### 2. 데이터베이스 스키마

**패턴:**
```
"[테이블명] 테이블을 위한 [DB] 스키마를 만들어줘.

컬럼:
- [컬럼명] ([타입], [제약조건])
- ...

인덱스:
- [컬럼명들]"
```

**예제:**
```
"products 테이블을 위한 D1 스키마를 만들어줘.

컬럼:
- id (INTEGER PRIMARY KEY AUTOINCREMENT)
- name (TEXT NOT NULL)
- price (INTEGER NOT NULL)
- category (TEXT NOT NULL)
- stock (INTEGER DEFAULT 0)
- created_at (TEXT NOT NULL)
- updated_at (TEXT)

인덱스:
- category
- created_at"
```

### 3. 프론트엔드 페이지

**패턴 (ViewLogic):**
```
"[페이지명] 페이지를 만들어줘. ViewLogic 패턴 사용.

기능:
- [기능 1]
- [기능 2]

API:
- [엔드포인트] - [설명]"
```

**예제:**
```
"제품 목록 페이지를 만들어줘. ViewLogic 패턴 사용.

기능:
- 제품 목록 표시 (카드 형태)
- 카테고리별 필터링
- 검색 기능
- 페이징

API:
- GET /api/products?page=1&limit=20&category=&search="
```

## 코드 수정 패턴

### 1. 리팩토링

**패턴:**
```
"[파일/함수]를 리팩토링해줘.

개선사항:
- [개선 1]
- [개선 2]"
```

**예제:**
```
"src/services/userService.js의 createUser 함수를 리팩토링해줘.

개선사항:
- 함수가 너무 길어. 작은 함수로 분리
- 검증 로직을 별도 함수로
- 에러 메시지를 더 구체적으로"
```

### 2. 버그 수정

**패턴:**
```
"[파일]에서 [문제]가 발생해. 원인을 찾아서 고쳐줘."
```

**예제:**
```
"src/routes/products.js에서 GET /products/:id가 항상 null을 반환해.
원인을 찾아서 고쳐줘."
```

### 3. 기능 추가

**패턴:**
```
"[파일/기능]에 [새 기능]을 추가해줘.

요구사항:
- [요구사항 1]
- [요구사항 2]"
```

**예제:**
```
"src/routes/products.js에 검색 기능을 추가해줘.

요구사항:
- GET /products?search=keyword
- name, description에서 검색
- 대소문자 구분 없이"
```

## 분석 패턴

### 1. 코드 리뷰

**패턴:**
```
"[파일/PR]을 리뷰해줘.

체크 항목:
- [항목 1]
- [항목 2]"
```

**예제:**
```
"src/routes/users.js를 리뷰해줘.

체크 항목:
- 보안 취약점
- 성능 문제
- 코드 품질
- 베스트 프랙티스 준수"
```

### 2. 에러 진단

**패턴:**
```
"[에러 메시지]

이 에러가 왜 발생하는지 설명하고 해결 방법을 알려줘."
```

**예제:**
```
"TypeError: Cannot read property 'id' of undefined
at getUser (userService.js:45)

이 에러가 왜 발생하는지 설명하고 해결 방법을 알려줘."
```

### 3. 코드 설명

**패턴:**
```
"[파일/함수]의 동작 원리를 설명해줘.

초점:
- [초점 1]
- [초점 2]"
```

**예제:**
```
"src/middleware/auth.js의 동작 원리를 설명해줘.

초점:
- JWT 검증 과정
- 에러 처리
- 사용자 정보 추출"
```

## 테스트 패턴

### 1. 단위 테스트 생성

**패턴:**
```
"[클래스/함수]에 대한 단위 테스트를 작성해줘.

테스트 케이스:
- [정상 케이스]
- [에러 케이스]
- [엣지 케이스]

프레임워크: [Jest/Vitest]"
```

**예제:**
```
"UserService의 createUser 메소드에 대한 단위 테스트를 작성해줘.

테스트 케이스:
- 유효한 데이터로 생성 성공
- 이메일 중복 시 에러
- 이메일 형식 오류 시 에러
- 필수 필드 누락 시 에러

프레임워크: Jest"
```

### 2. 통합 테스트 생성

**패턴:**
```
"[API 엔드포인트]에 대한 통합 테스트를 작성해줘.

시나리오:
- [시나리오 1]
- [시나리오 2]"
```

**예제:**
```
"POST /api/users 엔드포인트에 대한 통합 테스트를 작성해줘.

시나리오:
- 정상 생성 (201)
- 이메일 중복 (400)
- 인증 없음 (401)
- 필수 필드 누락 (400)"
```

## 문서화 패턴

### 1. README 생성

**패턴:**
```
"이 프로젝트의 README.md를 작성해줘.

포함 내용:
- 프로젝트 설명
- 기술 스택
- 설치 방법
- 실행 방법
- 주요 기능
- API 문서 링크"
```

### 2. API 문서 생성

**패턴:**
```
"[API들]에 대한 API 문서를 작성해줘.

포맷: [Markdown/OpenAPI]
포함 내용:
- 엔드포인트
- 요청/응답 예제
- 에러 코드"
```

**예제:**
```
"User API에 대한 API 문서를 작성해줘.

포맷: Markdown
포함 내용:
- 모든 엔드포인트
- 요청/응답 예제
- 에러 코드
- 인증 방법"
```

## 고급 패턴

### 1. 다단계 작업

**패턴:**
```
"다음 작업을 순서대로 진행해줘:

1. [작업 1]
2. [작업 2]
3. [작업 3]

각 단계 완료 후 결과를 보여줘."
```

**예제:**
```
"다음 작업을 순서대로 진행해줘:

1. Product 테이블 스키마 생성 (D1)
2. ProductService 클래스 생성 (CRUD 메소드)
3. Product 라우트 생성 (API 엔드포인트)
4. 단위 테스트 작성

각 단계 완료 후 파일 목록을 보여줘."
```

### 2. 조건부 작업

**패턴:**
```
"[조건]을 확인하고,
- [조건]이면 [작업 A]
- 아니면 [작업 B]"
```

**예제:**
```
"src/services/productService.js가 있는지 확인하고,
- 있으면 updateProduct 메소드만 추가
- 없으면 전체 ProductService 클래스 생성"
```

### 3. 비교 및 선택

**패턴:**
```
"[옵션 A]와 [옵션 B] 중 어느 것이 더 나은지 비교하고 추천해줘.

비교 기준:
- [기준 1]
- [기준 2]"
```

**예제:**
```
"KV 캐시와 메모리 캐시 중 어느 것이 더 나은지 비교하고 추천해줘.

비교 기준:
- 성능
- 비용
- 확장성
- 구현 복잡도

우리 프로젝트는 Cloudflare Workers를 사용해."
```

## 프롬프트 조합 팁

### 1. 컨텍스트 + 명확한 지시

```
"현재 프로젝트는 Hono + D1 + KV를 사용하는 Workers 프로젝트야.
UserService를 참고해서 ProductService를 만들어줘.
동일한 패턴(클래스 기반, KV 캐시 우선)을 사용해줘."
```

### 2. 예제 + 요구사항

```
"src/routes/users.js를 참고해서 src/routes/products.js를 만들어줘.

추가 요구사항:
- 카테고리별 필터링 추가
- 가격 범위 검색 추가
- 재고 수량 체크 추가"
```

### 3. 문제 + 제약사항

```
"로그인 API를 만들어줘.

제약사항:
- bcrypt로 비밀번호 해싱
- JWT 토큰 발급 (7일 만료)
- Rate Limiting (15분에 5번)
- 실패 시 로깅
- 3회 실패 시 계정 잠금"
```
