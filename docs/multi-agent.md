# 멀티 에이전트 활용

## 멀티 에이전트란?

바이브코딩에서 AI에게 일을 시키는 방법은 두 가지입니다:

| 방식 | 설명 | 적합한 상황 |
|------|------|------------|
| **싱글 에이전트** | AI 하나가 순차적으로 작업 | 단순 기능, 수정, 버그 픽스 |
| **멀티 에이전트** | 여러 AI가 역할별로 동시 작업 | 기능 단위 개발, 대규모 작업 |

멀티 에이전트는 **팀 리더가 팀원들에게 일을 분배하듯** AI가 여러 전문 역할을 동시에 실행하는 방식입니다.

```
team-lead (조율)
├── user-dev — 사용자 화면 개발
├── admin-dev — 관리자 화면 개발
├── api-dev — API 개발
├── dba — 데이터베이스
├── designer — UI/UX 디자인
├── qa — 테스트
└── publisher — 배포
```

## 왜 필요한가?

싱글 에이전트로 "게시판 만들어줘"라고 하면 AI가 **순차적으로** 작업합니다:

```
화면 만들기 → API 만들기 → DB 스키마 → 테스트 → ... (직렬)
```

멀티 에이전트는 **동시에** 작업합니다:

```
화면 만들기 ─┐
API 만들기 ──┼→ 통합 → 테스트
DB 스키마 ──┘
```

**효과:**
- 작업 시간 단축 (병렬 처리)
- 각 에이전트가 자기 영역에 집중하므로 품질 향상
- team-lead가 전체를 조율하므로 일관성 유지

## 단계별 시작하기

한 번에 8개 에이전트를 쓰는 건 고급입니다. 단계적으로 시작하세요.

### 1단계: 2개 에이전트 (프론트 + 백엔드)

가장 기본적인 분리입니다:

```
"게시판 기능을 만들어줘.
프론트엔드(app/pages/)와 백엔드(server/api/, server/dao/)를
동시에 만들어줘."
```

AI가 두 개의 subagent를 실행하여 화면과 API를 동시에 개발합니다.

### 2단계: 3~4개 에이전트 (역할 분리)

DB와 테스트를 분리합니다:

```
"게시판 기능을 만들어줘.

역할 분리:
- 화면 개발: app/pages/board/ 에 목록, 상세, 작성 페이지
- API 개발: server/api/board.js, server/dao/board.js
- DB 설계: schema.sql에 게시판 테이블 추가
- 테스트: 전체 기능 시나리오 테스트

동시에 진행하고 결과를 보고해줘."
```

### 3단계: 전체 팀 구성

대규모 기능을 개발할 때:

```
"회원 관리 + 게시판 + 관리자 대시보드를 한 번에 만들어줘.

역할:
- admin-dev: 관리자 화면 (app/pages/admin/)
- user-dev: 사용자 화면 (app/pages/)
- api-dev: 전체 API (server/api/, server/dao/)
- dba: DB 스키마 (schema.sql)
- designer: 레이아웃, 공통 컴포넌트 (app/layouts/, app/components/)
- qa: 완료 후 전체 테스트

각 역할이 작업할 폴더를 겹치지 않게 분리해서 진행해줘."
```

## 에이전트 역할 정의

### Skills로 정의하기

`.claude/skills/`에 에이전트 역할을 정의하면 일관된 결과를 얻을 수 있습니다:

```markdown
---
name: team-lead
description: 기능 요청을 분석하여 하위 에이전트에게 작업을 분배합니다.
---

당신은 팀 리드입니다.

## 작업 방식
1. 사용자의 기능 요청을 분석
2. 필요한 역할을 판단하여 subagent 실행
3. 각 에이전트의 작업 영역이 겹치지 않도록 분리
4. 결과를 취합하여 통합 확인

## 에이전트 역할
- @user-dev: 사용자 화면 (app/pages/)
- @admin-dev: 관리자 화면 (app/pages/admin/)
- @api-dev: API + DAO (server/api/, server/dao/)
- @dba: DB 스키마 (schema.sql)
- @designer: 레이아웃, 컴포넌트 (app/layouts/, app/components/)
- @qa: 테스트 (tests/)
- @publisher: 배포 (wrangler deploy)

## 규칙
- 각 에이전트의 작업 폴더를 명확히 분리할 것
- 모든 에이전트가 완료되면 통합 테스트 실행
- 충돌이 발생하면 즉시 보고
```

### CLAUDE.md에 에이전트 영역 명시

여러 에이전트가 동시에 작업할 때 같은 파일을 수정하면 충돌이 생깁니다. CLAUDE.md에 작업 영역을 명시하세요:

```markdown
## 에이전트 작업 영역

| 에이전트 | 담당 폴더 | 역할 |
|---------|----------|------|
| user-dev | app/pages/ (admin/ 제외) | 사용자 화면 |
| admin-dev | app/pages/admin/ | 관리자 화면 |
| api-dev | server/api/, server/dao/ | API + 데이터 접근 |
| dba | schema.sql, migrations/ | DB 스키마 |
| designer | app/layouts/, app/components/, app/assets/ | UI/UX |
| qa | tests/ | 테스트 |

주의: 각 에이전트는 자기 담당 폴더만 수정합니다.
server/index.js는 api-dev만 수정합니다.
```

## 모니터링

멀티 에이전트 실행 중 Claude Code에서 각 에이전트의 상태를 확인할 수 있습니다:

| 상태 | 의미 |
|------|------|
| `Idle for Xs` | 작업 완료 후 대기 중 |
| `Wandering...` / `Running...` | 현재 작업 진행 중 |
| `X tool uses` | 파일 읽기/쓰기 등 도구 사용 횟수 |
| `XXXk tokens` | 이 에이전트가 소비한 토큰 |

### 모니터링 포인트

**토큰 소비 확인:** 각 에이전트의 토큰 사용량을 확인하세요. 하나의 에이전트가 비정상적으로 많은 토큰을 쓰고 있다면 루프에 빠졌거나 불필요한 작업을 하고 있을 수 있습니다.

**완료 순서 확인:** 모든 에이전트가 완료되면 team-lead가 결과를 취합합니다. 특정 에이전트만 오래 걸린다면 작업 범위가 너무 큰 것일 수 있습니다.

**충돌 감지:** 여러 에이전트가 같은 파일을 수정하면 마지막에 쓴 에이전트의 내용만 남습니다. team-lead에게 "충돌 없는지 확인해줘"라고 요청하세요.

## 주의사항

### 토큰 비용

멀티 에이전트는 **토큰 비용이 큽니다.** 8개 에이전트를 동시에 실행하면 한 번에 1,000k+ 토큰을 소비할 수 있습니다.

| 방식 | 대략적 토큰 |
|------|-----------|
| 싱글 에이전트 | 50~100k |
| 2개 에이전트 | 100~200k |
| 4개 에이전트 | 200~500k |
| 8개 에이전트 | 500~1,200k |

**비용 절감 팁:**
- 작은 기능은 싱글 에이전트로 처리
- 멀티 에이전트는 기능 단위(게시판 전체, 회원 시스템 전체)에만 사용
- 단순 수정이나 버그 픽스에는 사용하지 않음

### 환경 구축이 더 중요해짐

8개 에이전트가 동시에 코딩하면 **환경이 부실할 때 문제가 8배로 커집니다.** CLAUDE.md, rules, hooks가 제대로 갖춰져 있어야 모든 에이전트가 일관된 코드를 생성합니다.

멀티 에이전트를 쓰기 전에 반드시 확인하세요:

- [ ] CLAUDE.md에 프로젝트 맥락이 명확한가?
- [ ] rules에 핵심 코딩 규칙이 있는가?
- [ ] hooks가 규칙 위반을 자동으로 잡는가?
- [ ] 에이전트별 작업 영역이 분리되어 있는가?

### 작업 영역 분리가 핵심

멀티 에이전트의 가장 큰 리스크는 **파일 충돌**입니다. 두 에이전트가 같은 파일을 동시에 수정하면 하나의 변경이 사라집니다.

**좋은 분리:**
```
user-dev → app/pages/board/
admin-dev → app/pages/admin/board/
api-dev → server/api/board.js, server/dao/board.js
```

**나쁜 분리:**
```
user-dev → 게시판 화면 + API  ← 영역 겹침
api-dev → 게시판 API + 회원 API  ← 영역 겹침
```

## 언제 멀티 에이전트를 쓸까?

| 상황 | 추천 방식 |
|------|----------|
| 버그 수정, 작은 기능 추가 | 싱글 에이전트 |
| 한 페이지 개발 | 싱글 에이전트 |
| CRUD 기능 한 세트 (화면 + API + DB) | 2~3개 에이전트 |
| 대규모 기능 (회원 + 게시판 + 관리자) | 4~8개 에이전트 |
| 프로젝트 초기 전체 구조 생성 | team-lead + 전체 팀 |
