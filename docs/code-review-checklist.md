# 코드 리뷰 체크리스트

## 개요

Claude Code가 생성한 코드를 **체계적으로 리뷰**하기 위한 체크리스트입니다.

## 빠른 체크리스트

모든 코드 리뷰 시:

- [ ] **기능**: 요구사항 충족
- [ ] **보안**: 취약점 없음
- [ ] **성능**: 병목 없음
- [ ] **테스트**: 테스트 작성
- [ ] **문서**: 주석 및 문서

---

## 상세 체크리스트

### 1. 기능성

- [ ] **요구사항 충족**: 모든 요구사항 구현
- [ ] **정상 동작**: 예상대로 작동
- [ ] **엣지 케이스**: 경계 조건 처리
- [ ] **에러 처리**: 예외 상황 처리

**확인 방법:**
```
프롬프트: "이 코드가 다음 요구사항을 모두 충족하는지 확인해줘:
1. 사용자 생성
2. 이메일 검증
3. 중복 체크
4. 환영 이메일 발송"
```

### 2. 코드 품질

#### 가독성
- [ ] **변수명**: 의미가 명확한가?
- [ ] **함수명**: 동작이 명확한가?
- [ ] **함수 길이**: 50줄 이내인가?
- [ ] **중첩**: 3단계 이하인가?
- [ ] **주석**: 필요한 곳에만 있는가?

**예제:**
```javascript
// ❌ 나쁜 변수명
const d = new Date();
const x = users.filter(u => u.a);

// ✅ 좋은 변수명
const today = new Date();
const activeUsers = users.filter(user => user.isActive);
```

#### 구조
- [ ] **레이어 분리**: Route, Service, Utils 분리
- [ ] **단일 책임**: 함수가 한 가지 일만 하는가?
- [ ] **DRY**: 중복 코드 없는가?
- [ ] **재사용성**: 다른 곳에서도 사용 가능한가?

#### 일관성
- [ ] **코딩 스타일**: 프로젝트 스타일 준수
- [ ] **명명 규칙**: camelCase, PascalCase 일관성
- [ ] **파일 구조**: 프로젝트 구조 준수

### 3. 보안

- [ ] **입력 검증**: 모든 입력 검증
- [ ] **SQL Injection**: Prepared Statement 사용
- [ ] **XSS**: 출력 이스케이프
- [ ] **인증**: JWT/세션 검증
- [ ] **인가**: 권한 체크
- [ ] **시크릿**: 환경 변수 사용
- [ ] **민감 정보**: 로그에 노출 안 됨

**보안 리뷰 프롬프트:**
```
프롬프트: "이 코드의 보안 취약점을 찾아줘.

체크 항목:
- SQL Injection
- XSS
- CSRF
- 하드코딩된 시크릿
- 권한 체크 누락
- 입력 검증 누락"
```

### 4. 성능

- [ ] **DB 쿼리**: 최적화되었는가? (인덱스, JOIN)
- [ ] **N+1 문제**: 없는가?
- [ ] **캐싱**: 적절히 사용하는가?
- [ ] **병렬 처리**: Promise.all 활용
- [ ] **메모리**: 메모리 누수 없는가?
- [ ] **알고리즘**: 시간 복잡도 적절한가?

**성능 리뷰 프롬프트:**
```
프롬프트: "이 코드의 성능 문제를 찾아줘.

체크 항목:
- N+1 쿼리
- 불필요한 순차 실행
- 캐싱 기회
- 비효율적인 알고리즘"
```

### 5. 에러 처리

- [ ] **try-catch**: 필요한 곳에 있는가?
- [ ] **에러 메시지**: 구체적인가?
- [ ] **에러 타입**: 적절히 구분하는가?
- [ ] **로깅**: 중요 에러 로깅
- [ ] **사용자 메시지**: 친절한가?

**예제:**
```javascript
// ❌ 모호한 에러
throw new Error('Error');

// ✅ 구체적인 에러
throw new NotFoundError(`User not found: ${userId}`);
throw new ValidationError('Email format is invalid');
```

### 6. 테스트

- [ ] **단위 테스트**: 주요 함수 테스트
- [ ] **통합 테스트**: API 엔드포인트 테스트
- [ ] **커버리지**: 80% 이상
- [ ] **엣지 케이스**: 경계 조건 테스트
- [ ] **모킹**: 외부 의존성 모킹

**테스트 요청 프롬프트:**
```
프롬프트: "이 코드에 대한 테스트를 작성해줘.

요구사항:
- Jest 프레임워크
- 정상 케이스
- 에러 케이스
- 엣지 케이스"
```

### 7. 문서화

- [ ] **함수 주석**: JSDoc 작성
- [ ] **복잡한 로직**: 주석 설명
- [ ] **README**: 업데이트
- [ ] **API 문서**: OpenAPI/Swagger (선택)
- [ ] **CHANGELOG**: 변경사항 기록

## 플랫폼별 체크리스트

### Workers 체크리스트

- [ ] **서비스 레이어**: 클래스 기반
- [ ] **env 주입**: 생성자에서 주입
- [ ] **KV 캐시**: 적절히 활용
- [ ] **D1 쿼리**: Prepared Statement
- [ ] **바인딩**: Cloudflare 바인딩 사용

### Pages (ViewLogic) 체크리스트

- [ ] **HTML/JS 분리**: 완전 분리
- [ ] **CSS 분리**: HTML에 style 태그 없음
- [ ] **라우팅**: 파일명 = 라우트
- [ ] **레이아웃**: layout 설정
- [ ] **반응형**: Bootstrap 클래스 사용

### 맑은프레임워크 체크리스트

- [ ] **JSP/HTML 분리**: 완전 분리
- [ ] **try-catch 금지**: 프레임워크 메소드 사용
- [ ] **POST return**: POST 처리 후 return
- [ ] **파라미터**: m.rs(), f.get() 사용
- [ ] **Page 순서**: setLayout → setBody → display

## 리뷰 프로세스

### 1단계: 자동 리뷰 (Claude Code)

```
프롬프트: "이 PR의 코드를 리뷰해줘.

체크 항목:
1. 기능성 (요구사항 충족)
2. 보안 (취약점)
3. 성능 (병목)
4. 코드 품질 (가독성, 구조)
5. 에러 처리

각 항목별로 ✅/❌/⚠️로 표시하고, 문제가 있으면 구체적으로 설명해줘."
```

### 2단계: 수동 리뷰

자동 리뷰에서 놓칠 수 있는 것:
- 비즈니스 로직의 정확성
- UX/UI 일관성
- 팀 컨벤션 준수

### 3단계: 수정 및 재검토

```
프롬프트: "리뷰 피드백을 반영해서 코드를 수정해줘.

피드백:
1. SQL Injection 취약점 수정
2. 함수 분리 (너무 긴 함수)
3. 에러 메시지 구체화"
```

## 리뷰 코멘트 템플릿

### 긍정적인 피드백

```
✅ 좋습니다!
- 레이어 분리가 명확합니다
- 에러 처리가 잘 되어 있습니다
- 테스트 커버리지가 높습니다
```

### 개선 제안

```
⚠️ 개선 제안:
- 함수가 너무 깁니다 (100줄). 작은 함수로 분리하는 것이 좋겠습니다
- 변수명이 모호합니다. `data` → `userData`로 변경 제안
- SQL Injection 취약점이 있습니다. Prepared Statement 사용 필요
```

### 필수 수정

```
❌ 필수 수정:
- 하드코딩된 API 키가 있습니다. 환경 변수로 이동 필요
- 권한 체크가 없습니다. 인가 미들웨어 추가 필수
- 테스트가 없습니다. 최소한 단위 테스트 작성 필요
```
